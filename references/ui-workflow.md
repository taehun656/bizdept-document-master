# 문서 설정 UI 워크플로우

## 목적

`slide-master`의 확인 UI처럼 문서 생성을 시작하기 전에 주제, 템플릿, 스타일, 출력 형식과 첨부자료를 한 화면에서 확정한다. UI는 문서를 직접 생성하지 않고, 이후 파이프라인이 따를 사용자 선택값을 저장한다.

## 실행

먼저 작업 폴더를 정하고 UI 서버를 실행한다.

```bash
node <skill-root>/scripts/document-ui/server.mjs <project-path>
```

- 서버는 사용 가능한 임의 포트의 `127.0.0.1`에만 바인딩한다.
- 기본적으로 브라우저를 자동으로 연다.
- 브라우저 자동 실행을 막으려면 `--no-browser`를 붙인다.
- 포트를 고정하려면 `--port 5052`를 붙인다.
- 콘솔의 `DOCUMENT_UI_URL=` 뒤 주소를 브라우저에서 열 수 있다.
- 사용자가 확정하면 서버가 자동으로 종료된다.

## 선택과 저장

1. 주제: 범위, 제목, 작성 목적, 보고 대상, 추가 지시
2. 템플릿: 6개 내장 템플릿 또는 `내 양식 파일`
3. 스타일: 문장 톤, 문서 구성, HWPX·DOCX 출력 여부
4. 원시자료: 결재 PDF와 근거 파일

`내 양식 파일`을 고르면 HWPX 또는 DOCX 파일이 필수다. 바이너리 HWP는 원시자료로 읽을 수 있지만 편집 양식으로 선택하지 않는다.

확정 전에는 선택한 로컬 파일을 복사하지 않는다. 확정하면 다음 위치에 저장한다.

```text
<project>/
├── sources/uploads/         원시자료
├── sources/reference/       참조 HWPX·DOCX 양식
└── spec/ui-selection.json   확정한 설정값
```

파일당 최대 크기는 50MB다. 같은 이름이 이미 있으면 `(2)`, `(3)` 접미사를 붙여 기존 파일을 덮어쓰지 않는다.

## 결과 처리

UI 프로세스가 끝나면 `spec/ui-selection.json`을 읽는다. 이 파일의 다음 값은 사용자 확정값이다.

- `topic`: 범위, 제목, 목적, 독자, 추가 지시
- `template`: 템플릿 ID와 표시 이름
- `style`: 문장 톤과 문서 구성
- `outputs`: `hwpx`, `docx`
- `attachments`: 역할, 파일명, 프로젝트 상대경로, 크기

이 값을 원천자료 분석 결과와 결합하여 `document_spec.md`, `spec_lock.yaml`, `content.md`를 만든다. 선택한 출력 형식이 하나뿐이면 요청하지 않은 다른 형식을 만들지 않는다.

## 대화형 대체 경로

브라우저 또는 로컬 포트를 사용할 수 없으면 다음 질문을 한 번에 제시한다.

1. 문서 제목과 작성 목적은 무엇인가?
2. 누구에게 보고하는가?
3. 6개 내장 템플릿과 기존 양식 중 무엇을 사용할 것인가?
4. 간결 결재형, 표준 보고형, 설명 강화형 중 어떤 문장 스타일인가?
5. 1쪽 요약형, 표준형, 근거 상세형 중 어떤 구성인가?
6. HWPX와 DOCX 중 어떤 형식이 필요한가?
7. 분석할 원시자료와 참조 양식은 무엇인가?

답변을 같은 `ui-selection.json` 구조로 정규화한 뒤 나머지 워크플로우를 계속한다.
